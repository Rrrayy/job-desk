# BOSS 直聘适配器

P0 适配器。**它只做一件事**：把从 BOSS 页面复制出来的纯文本，解析成 `NormalizedRecord[]`。

协议总览见 [`docs/adapters/README.md`](../../../../docs/adapters/README.md)，
这里只写 BOSS 特有的东西。

---

## 1. 页面形态

两种页面，都能被用户整页复制：

| 页面 | URL 特征 | 抓到的内容 |
| --- | --- | --- |
| 沟通列表 | `zhipin.com/web/geek/chat` | 每家：公司名 / 岗位名 / 城市 / 最后一条消息 / 相对时间 |
| 投递列表 | `zhipin.com/web/geek/apply` | 每家：公司名 / 岗位名 / 城市 / 薪资 / 状态（已投递 / 已查看 / 邀请面试 / 不合适） |
| 求职记录（App） | 无 URL，整页复制粘贴 | 每家：岗位名 / 薪资 / 公司名 / 城市 / 时刻（日期在分组标题行）；**无状态行** |

`matchUrl` 同时命中两条前缀：

```ts
matchUrl: (url) => /zhipin\.com\/web\/geek\/(chat|apply)/.test(url)
```

## 2. 解析策略

1. **切块**：先按空行切；BOSS 的空行不可靠（部分卡片没有），再按「以时间行收尾」切一遍，
   两种切法各算一次「认出的公司名数量」，谁多取谁（`shared.ts` 的 `parseListLike`）。
2. **抽字段**：公司名靠「收尾词 + 长度」启发式（`looksLikeCompany`），岗位名靠岗位关键词
   （`looksLikeJobTitle`），状态靠 `STATUS_HINTS`，时间靠 `extractTime`（认「今天/昨天/前天」与
   「3月12日」「12:30」）。
3. **求职记录页预处理**（`normalizeRecordPage`）：丢页面头噪声；把分组日期（「10月21日」）
   下放到其后的裸时刻行（「14:12」→「10月21日 14:12」），否则跨组日期全算「今天」；
   公司行剥离「A轮 500-999人」这类融资/规模后缀；地点行剥离「5天/周 6个月 本科」标签。
4. **置信度**：公司名与岗位名都认出来 → `high`；只有一个 → `medium`；靠兜底猜的 → `low`。
   `overall` 取各字段最小值。
5. **失败**：拿不到公司名的块进 `unparsed`，原因写「这一行没有公司名」。**绝不编造**。

## 3. Fixtures

| 文件 | 覆盖什么 |
| --- | --- |
| `chat-list.txt` | 沟通列表正常形态（4 家，含「昨天」「3月10日」两种时间） |
| `apply-list.txt` | 投递列表正常形态（含「邀请面试」「不合适」） |
| `record-list.txt` | 求职记录页真机形态（2026-10-21 校准；分组日期 / 融资规模 / 周期标签 / 无状态行） |
| `empty.txt` | 空输入 → `records: []` + 一条 `unparsed`（不是静默空） |
| `garbage.txt` | 导航栏、按钮、页码混在一起 → 大部分落 `unparsed`，不崩 |
| `expected.json` | 上面两个正常 fixture 的期望输出快照 |

**fixture 已脱敏**：公司名与岗位名保留（公开投递事实），人名一律 `HR`，
手机号 / 邮箱 / 微信号 / 内推码已删除。加 fixture 时请遵守同一条规矩。

## 4. 已知限制

- **不读 DOM**：只吃文本。图标状态（纯图形、无 alt）读不出来 → 落「待归类」让用户手选。
- **不区分发信方**：「沟通中」一律按高置信度 `chatting`（架构 §8-歧义 3）。
- **求职记录页没有状态行**：「沟通过」tab 复制出来的记录 `status` 为空、置信度 `low`，
  由同步引擎按低置信度处理（进 staging 供用户确认），不猜状态。
- **不翻页**：用户复制的是当前渲染出来的部分，虚拟滚动会截断（UI 有提示）。
- **「邀请面试」只映射到 `chatting` + 一条待办**：不自动进 `scheduled`、不自动造 Interview。
  约在第几轮、约在几点，只有用户知道。
- **相对时间的跨零点误差**：「昨天 23:50」在今天早上 00:10 抓，可能差一天。接受。

## 5. 页面改版了怎么办

1. 先让用户确认「整页复制」还能不能用 —— 文本形态通常比 DOM 稳。
2. 把新形态脱敏后加成 `fixtures/*-new.txt`，测试里同时断言新旧（老页面缓存还在）。
3. 优先放宽 `shared.ts` 里的启发式（加一个公司名收尾词、加一个状态正则），
   而不是在 `parse.ts` 里写死某一行文本。
4. 改完更新 `lastVerifiedAt`，并说明你**真的**看过页面。

完整流程见 [`docs/adapters/README.md`](../../../../docs/adapters/README.md) 第 5 节。
