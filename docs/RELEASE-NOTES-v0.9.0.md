# RELEASE NOTES v0.9.0

主题：**简历模块**。投递台账之外，这个工具第一次有了「简历」这个一等公民：
8 套模板、A4 所见即所得预览、浏览器直接打印、版本冻结与投递绑定，以及四个
新的 AI 场景和「整段面经一键拆题」。数据格式 schemaVersion 4 → 5（纯增量，
老数据零影响），AI 产出的每一条写入依旧走「预览 → 逐条确认 → 可撤销」。

---

## 1. 新增

### 简历模块（一级页，导航第 6 项，快捷键 6）

- **8 套模板**：tech-single / campus-general / social-simple / minimal-bw（P0）+
  tech-double / product-ops / academic / creative（P1）。数据是超集、模板只是视图：
  切模板不丢任何字段；模板独有字段永远留在内容里。
- **A4 所见即所得预览 + 打印**：预览与打印同一份 DOM、同一套 CSS（mm 单位），
  缩放只缩外壳不缩字号；`@page size:A4; margin:14mm` 全仓唯一一份静态规则；
  分页保护（条目不跨页切断、板块标题不孤行）；打印时自动隐藏画布装饰，
  只留简历本体。导出 PDF = 浏览器打印里的「另存为 PDF」，不引入任何 PDF 库。
- **版本生命周期**：新建 / 复制（不带历史）/ 重命名（id 不变，统计不漂移）/
  切模板（内容不丢）/ 另存为版本 / 设主版本 / 软删恢复 / 永久删除；
  每份简历 ≤30 个版本，第 28 个开始菜单里出现灰字提醒。
  **版本一经冻结不可变**——要改它，用「以此版本为草稿」。
- **投递 ↔ 版本双向绑定**：投递记录选择绑定的简历版本；改绑留痕
  （`resumeBindLog`，≤20 条，不改活跃度、不写时间线——沉默天数不被污染）；
  版本删除后投递侧显示「（已删除）」并说明「投递记录保留」。
- **统计联动**：简历页每份简历显示「投递 N · 进面 M（面试率）」；
  样本 <20 不显示百分比（样本不足的率会骗人）；旧数据（只有简历文本的投递）
  统一归入「未绑定（旧数据）」桶。

### AI 场景（v0.8 的三个之外新增五个入口）

- **d19-polish 段落润色**：选中简历里的一个条目，AI 给出改写建议；
  采纳后写进**草稿**（冻结版本永远不被 AI 碰），⌘Z 可逐字段还原。
- **d19-jd JD 定向**：粘贴 JD + 勾选模块，AI 给出逐字段修改建议（附依据）。
- **d19-diag 简历诊断**：AI 按维度给出 strong/partial/gap/not_found 判定 +
  证据对照 + 正文摘要；顶部分数由**本地代码合成**，标注「仅供参考」。
- **d20-analysis 投递分析**：投递详情页一键分析「这份简历对这个 JD 的匹配度」。
  `not_found`（材料里没提到）不计入分母；全部维度 not_found 时不显示分数。
- **d14-bulk 面经整段录入**：粘贴一整段复盘笔记，只标头部（公司/岗位/时间），
  AI 自动拆题、编号、归类；未识别为题目的原文默认保留进备注（带前缀，
  不吞一字）；最多 50 题；编号与分类由代码决定，不听模型的。
- 全部场景延续 v0.8 铁律：**发送前强制预览、逐条确认才落库、⌘Z 可撤销**；
  联系方式（姓名/电话/邮箱）在任何场景都结构上不可出境。

## 2. 数据与隐私

- schemaVersion 4 → 5：新增 `resumes` / `resumeVersions` / `aiReports` 三张表
  与 `Application.resumeVersionId` 字段，纯增量，老数据自动迁移、零影响。
- `AIReport` 只读产出：不写投递数据；每目标最多保留 3 份、总量 200 份；
  模型输出的 summary/next_steps 拼进正文，不落独立字段。
- RequestLog 继续不记请求体与响应体原文；五个新场景每次发送恰一条日志。

## 3. 体积：为什么是本版这个数（产品决策，如实记录）

v0.9 立项时预算落点 ≈678 KB（WARN 690 / FAIL 715）。开发过程中三次如实记账：

1. **tree-shaking 阶梯**：T02–T04 的组件在接线前不进产物（账面涨幅远低于
   真实成本），T05 接线时一次性兑现 30.9 KB（逐文件 metafile 归因）。
2. **T07 四场景实测 +17.9 KB**（预算 14）：报告卡一张两用、窄校验复用都已做，
   剩余构成是四个场景的解析器与测试覆盖的 UI 文案——再压就要砍可读性。
3. **主理人裁决：抬线**。WARN 690 → **705**，FAIL 715 → **730**。
   理由：本版新增是「简历模块 + 5 个 AI 场景」一整个能力域，构成里没有
   依赖膨胀（React 硬地板 142 KB 未变、零新增运行时依赖）；
   FAIL 抬幅（+15）保持「再做一个小功能才需要回头优化」的手感，
   不复制 v0.3 批评过的「空白支票」。

## 4. 已知限制

- **打印的浏览器差异**：Firefox/Safari 的分页与 `print-color-adjust` 表现
  与 Chrome/Edge 不一致，未做适配（推荐 Edge/Chrome 打印）。
- **看板性能**：1000 条数据切换约 180–330 ms（视机器），未做虚拟化；
  500 条以内无感。`buildResumeStats` 为单遍 O(N) 聚合，500 条 <20 ms。
- **quick note 的 `category` 修复依赖 d14-bulk**：v0.8 已知限制「快记题目
  类别无法落库」在本版由整段录入路径修复；逐题手录路径不变。
- **照片上传**仅在 creative 模板启用（≤480px、≤80 KB 自动压缩）。

## 5. 升级与回滚

- 覆盖 `index.html` 即完成升级，localStorage 数据自动迁移（4 → 5）。
- 回滚到 v0.8.0：直接用旧 `index.html` 覆盖即可——v0.9 的 schema 是
  v0.8 的超集，v0.8.0 的 `validateImport` 会拒绝 v5 备份文件
  （旧版范围校验不含 v5）；**回滚前先用 v0.9 导出一份 JSON 备份**。
