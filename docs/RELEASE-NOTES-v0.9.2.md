## 2. 视觉：为什么只改这五处

这一版刻意**不做视觉改版**。五处改动都满足两个条件：用户能感知、且不需要视觉方向上的争论。

### 2.1 幽灵按钮（`btn--ghost`）

v0.9.1 审计发现 8 处 `className="btn btn--small btn--ghost"` 之类的按钮，
`styles.css` 里只有 `.btn--danger-ghost` —— 这些按钮当前的视觉与裸 `.btn` 完全相同。
它们承担的是「取消 / 跳过 / 断开连接」这类**次要动作**，却和「去投递」长得一样，
用户在弹窗里没有视觉锚点判断哪个是主操作。

现在：透明底、无边框、靛蓝文字、hover 出现浅紫底（`--indigo-soft`）。
主按钮（实底）/ 普通按钮（白底带框）/ 幽灵按钮（无底无框）三档层级变得可读。

同时把 `scripts/tokenize-classes.mjs` 的 `KNOWN_UNSTYLED_ATOMS` 从 `['btn--ghost']`
改成空集：白名单的存在意义是「已知例外」，例外修好了还不摘，等于给自己留后门。

### 2.2 按压反馈（`:active`）

`.btn` 和 `.icon-btn` 按下时下沉 1px。`transition: all .15s` 早就写了，
但此前只有 hover 有反馈，点击瞬间没有「按下去了」的物理感 —— 高频操作（拖动前点按钮、
连续点「去催一下」）时尤其明显。`disabled` 不参与，避免灰按钮看起来还能点。

### 2.3 细滚动条

看板的横向滚动、抽屉与列表的纵向滚动此前都是操作系统默认粗条（Windows 下 17px 带箭头），
在 8 套简历模板那样讲究留白的界面里非常割裂。现在：
Firefox 用 `scrollbar-width: thin` + `scrollbar-color`，
Chromium / Safari 用 `::-webkit-scrollbar`（8px、圆角、浅灰 `#c9cdda`、hover 加深）。
打印媒体不渲染滚动条，`check:print` 95 条断言不受影响。

### 2.4 `prefers-reduced-motion`

新增一个媒体查询：动效敏感用户（前庭功能障碍等）的所有 `transition` / `animation`
即时完成。**不改变普通用户的任何观感** —— 这是纯增量规则，没有覆盖任何既有样式。

### 2.5 次要文字对比度（`--ink-4`）

`#9aa0b4` 在白底上对比度约 2.7:1，低于 WCAG AA 对正文的 4.5:1，也低于大字的 3:1。
它用在页脚、快捷键提示、「数据只在本地」这类**不承载关键信息但需要读**的位置，共 53 处。
调到 `#8a91a6`（~3.5:1）：肉眼可感知地更清楚，又不至于抢主文字的层级。
`--ink` / `--ink-2` / `--ink-3` 一律不动 —— 那三档是信息层级的骨架。

## 3. 测试债：还了哪三笔

### 3.1 `SettingsDrawer` 交互（19 条，最大一笔）

v0.9.1 只有 2 条「薄挂载」断言：证明简历回收站子区**被挂上了**。
但设置页 400+ 行里的按钮接线从未被测过 —— 把 `extendTrash(id)` 写成
`restoreApplication(id)`，用户点「再留 7 天」会变成恢复投递，而测试全绿。

覆盖范围（每条都断言**方法名 + 实参**，不只断言「被调过」）：

- 阈值失焦写回 `{warnAfterDays: 5}`；`0 / 负数 / 空`一律不写回（保护出厂值）
- 默认简历版本去首尾空格后写回
- 备份提醒选「不提醒」写回 `0`（0 是合法值，不是被 `||` 吃掉）
- 四个导出按钮各接各的方法（JSON / CSV / ICS / 便携包不许串线）
- 文件导入把 `File` 交给 `importData` 并把 input 复位（同一文件连选两次都能触发）
- 导入失败横幅显示具体原因，「知道了」接 `onDismissError`
- **两步确认全覆盖**：清空全部数据 / 加载示例 / 清空回收站 / 永久删除 ——
  第一次点击一律断言**不调用**，确认后才调用；取消路径也测了
- 单条恢复 / 再留 7 天带的是**这条**的 id
- 同步设置：默认平台写回完整 `sync` 对象；「关」写回布尔 `false` 而非字符串
- 重置风险确认：仅在 `riskAckAt` 存在时出现，写回 `undefined` 并 toast
- 遮罩点击关闭 / 抽屉内点击不关闭（`stopPropagation` 真的在）
- 「去日历导入课表」同时发生「切视图 + 关抽屉」两个动作
- 存储用量渲染 `checkStorage` 的真实比例

**变异验证**：把 `extendTrash` 故意错接成 `restoreApplication`，对应用例立刻转红
（1 failed / 18 passed），恢复后全绿。这条流程写在这里，是为了让后来的人知道
「测试绿」不是随手说的。

### 3.2 `App.tsx` 冒烟（4 条）

3,380 行的主组件此前没有任何测试 import 它。全量补测不现实（等于把产品再测一遍），
所以只钉**只有 App 能证明的四件事**：

1. 空环境首屏是欢迎页（不是白屏、不是崩溃兜底页）；
2. 加载示例后 8 家公司进看板（`api → state → 视图`接线通）；
3. 数据真的落进 `localStorage`（不是内存幻觉）；
4. 重新挂载直接进主界面（欢迎页只在首次出现，不能每次都拦路）。

外加一条快捷键冒烟：`2` 能切到看板（键盘导航接线没断）。

**边界写在测试头注释里**：这是启动路径冒烟，不是全量覆盖。视图内部行为仍由
各自的组件测试与 `smoke-*.mjs`（CDP 真浏览器）守着。

> 一个测试实现细节：看板的「已结束」列默认折叠，8 家公司只渲染 7 张卡。
> 断言写成「可见卡 ≥ 7 + `localStorage` 里必须是 8 条」，而不是傻等 8 张卡 ——
> 折叠是 v0.9.1 的设计，不是 bug。

### 3.3 两条 lint warning

`BulkAdoptInput` / `BulkAdoptResult` 原先写成内联 `import('../ai/experienceBulk').X`，
被 `@typescript-eslint/consistent-type-imports` 记为 warning。改成顶层
`import type` + `export type` 重新导出：

- 类型在编译期擦除，**零运行时依赖**；
- 不会形成环（`experienceBulk` 只反向依赖 `types` / `lib/util` / `ai/scenarios`）；
- `npm run lint` 现在 0 error **0 warning**。

## 7. 已知问题（诚实边界）

- **`App.tsx` 仍是 3,380 行、仍是全仓最大单文件**。本版给它补了启动路径冒烟，
  不等于有完整覆盖；后续改动请继续保持「不在 App 里堆不可测分支」的纪律。
- **视觉改动没有像素级回归门禁**。本版的验收方式是「真实浏览器截图 + 人工确认」
  （`app/shots-ux-v092/`），不是自动 diff。若后续要改视觉，请沿用同样方式留证据。
- **`prefers-reduced-motion` 只关动效，不改布局**。如果未来引入「靠动画表达状态变化」
  的交互，需要单独确认该交互在减少动效模式下仍有非动画的表达方式。
