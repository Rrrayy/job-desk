# v0.8.0 — AI 帮忙，但你说了算 + 求职管线扩到「已笔试」

发布日期：2026-10-22 · tag `v0.8.0`（发版时由主理人打）· 基线 commit `8c94fcd`（T04）

主题：**把「AI 帮忙」做成一件敢用的事。** 三件原本只能手工做的事（面经整理、沟通话术、
解析失败的记录）交给你自己选的模型 —— 但每一次请求前都必须先看清「要发出去的是什么」，
每一个产出都必须逐条勾选才会落库。同一版里，求职管线补上了「已笔试」与轮次类型，
看板从 6 列扩到 7 列。

---

## 1. 三个 AI 场景（R-AI-1 / R-AI-2 / R-AI-3）

三个场景共用同一条主干，主干只有一份实现（`src/ai/scenarios.ts` + `components/ai/AiScenarioPanel.tsx`）：

```
用户在面板里准备好输入
   → 预览（SendPreviewDialog，强制弹层，逐字段勾选）
   → 发送（App.runAiScenario：唯一 fetch 点 + 一条 RequestLog）
   → 窄校验（模型输出必须符合约定形状，失败 = 零写入 + 一句人话）
   → AISuggestion(pending) 逐条勾选
   → api.ai.acceptSuggestions（单次 mutate + 一个撤销点）
   → ⌘Z 整批回退
```

### D14 面经整理（入口：面经编辑器 →「🤖 用 AI 整理这段面经」）

- 默认出境 = **只发你粘贴的那段文字**（锁定项，视为已授权）；公司名 / 岗位是可选上下文，
  显式 `defaultChecked:false`，默认不勾。
- 产出：逐题建议（`targetType='question'`，`fieldPath='text'`）。
- 模型不按 JSON 输出时按「一行一题」兜底；一条题都认不出时诚实报错，不假装成功。

### D15 沟通话术草稿（入口：投递详情 →「🤖 生成沟通话术」）

- 默认出境 = 公司名 + 岗位名 + 当前状态（PRD Q8 定案）。
- 轮次 / 面试类型 / 面试官称呼 / 最近沟通记录是**显式追加项**（默认不勾）。
- 产出：一条 `application_note` 建议，确认后**追加**一条备注，不覆盖你写过的内容。

### D17 AI 辅助解析（入口：同步面板暂存区 →「🤖 用 AI 重试解析」）

- 铁律：**只发送用户粘贴的原文**。请求体的 user 消息就是原文本身（不加标签、不拼库内数据），
  所以「实际发出去的内容 == 你粘贴的内容」是一个可断言的等式（见 `scenarios.test.ts`）。
- 只在 `unparsed`（没解析出来）与 `unmapped`（状态没认出来）的行上出现 ——
  `ambiguous` / `conflict` 缺的是你的判断，不是认字，模型帮不上忙。
- 产出逐字段建议 + **证据对照**（模型依据的原文片段）；
  确认后**只写 `staging.parsed`（缓冲表）**，绝不碰 `applications`；
  归到哪个阶段仍然走你熟悉的那一步（行内状态下拉 → 建投递）。
- 补出公司名后，该行的原因从「没解析出来」放开为「状态没认出来」，
  否则它永远卡在只读分支、补全等于白做；`⌘Z` 会把原因一并还原。

## 2. D13 发送数据预览（强制，R-PLUGIN-3）

- 不可跳过、不可「记住选择」，确认一次只授权一次发送。
- 默认勾选基线：`companyName / jobTitle / status` ∪ 锁定项（用户粘贴的原文）。
- 新增出境字段（轮次 / 面试类型 / 笔试结果 / 面经原文 / 沟通记录）**默认一律不勾**，
  基线断言在 `SendPreviewDialog.test.tsx` 里，改基线必须改测试。
- 顶部显示模型名 + 完整端点；本机地址追加「本机端口，请求不出公网」。
- 未配置 / 断网：入口置灰 + 就地一行原因，不弹错误框（R-AI-5）。

## 3. 插件体系（D11 / D12 / R-PLUGIN-1、R-SEC-1）

- **沙箱**：插件跑在 `srcdoc` iframe，CSP `connect-src 'none'` —— 插件自己发不出任何网络请求。
- **能力全靠宿主代理**：postMessage RPC（带版本号 + pluginId + 请求 id），逐条校验来源与信封；
  权限清单逐项授权（读投递 / 写投递 / AI 请求 / 存储），未授权即拒绝并记日志。
- **存储隔离**：`PluginStorage` 主键物理化为 `pluginId::key`，跨 pluginId 读写一律拒绝。
- **AI 请求同样过 D13**：插件不能自带 fetch，也不能绕过预览；请求体字段与预览确认值不一致
  时宿主拒绝发送并记一条日志（D16 越权四类全部自动化）。
- **管理面板**：启用 / 禁用 / 卸载 / 权限查看 / 日志查看，全部在设置页。
- 插件包是独立分发的单个 html（示例 `app/plugins/notes-ai.plugin.html`），不进核心产物。

## 4. 数据迁移：schemaVersion 3 → 4

- **变的是三张新表**：`pluginStorage` / `requestLog` / `aiSuggestions`，纯 additive 空表落库。
  老数据（v0.7.3 真实备份）导入零错误、零字段损失。
- **迁移前写快照回滚点**（`jobdesk.v1.rollback.<from>.<ts>`，保留 30 天）；
  迁移幂等（连跑两次结果一致）；原子性靠「先校验、再写盘」。
- **失败即锁**：构造坏数据会进失败页并锁死写入（`lockPersistence`），原数据字节级不变，
  页面给三个出口（重试 / 用空数据进入 / 下载原文）。
- `formatVersion 2 → 3`；导出 JSON 剥离 `requestLog`（日志不随备份扩散），
  插件存储与 AI 建议随备份往返。
- 版本门禁：`check-versions` 保证「主应用 / 浏览器扩展 / 产物」三处版本号不各说各话。

## 5. 求职管线扩展（R-PIPE-1…5）

- `Status` 10 值（+`written`）：看板 7 主动列 + 已结束折叠；漏斗计数口径不变
  （`stageRankOf('written')=2.5`，仍落在「已投递」与「已约面」之间）。
- `Interview.kind`：笔试 = `round 0 + kind 'written'`；卡片徽章「第 2 轮 · 技术面」；
  没有轮次数据的老记录显示「轮次未记」。
- 挂点：`REJECT_ROUND_OPTIONS` 增「笔试（0）」，复盘挂点统计出现「笔试」档。
- CSV：导出增「当前轮次 / 面试类型」，导入识别别名（已笔试 / 笔试中 / 笔试通过 / 一面 / 技术面…），
  认不出的状态仍落「想投」并给**行级原因**，不静默丢。

## 6. 体积：红线 560 → 600 KB（产品决策，不是技术顺手）

### 决策

用户 2026-10-22 明确批准抬线（"不用砍功能 可以抬线"）。WARN 540 → 585、FAIL 560 → 600，
`npm run check:bundle` 的口径不变（未压缩 `dist/index.html` 字节数，1 KB = 1024 B）。

### 实测构成（v0.7.3 产物 545 KB 为起点）

| 任务 | 内容 | 实测增量 |
| --- | --- | --- |
| T01 | 数据层：迁移 3→4、`written`、CSV 往返 | ≈ +6.5 KB |
| T02 | 管线 UI：7 列看板 / 轮次徽章 / DropPanel 结构化写入 | ≈ +3.3 KB |
| T03 | AI 核心：gateway + SSE + 重试 + 建议生命周期 + 请求日志 | ≈ +3.7 KB |
| T04 | 插件宿主（broker / sandbox / storage / manifest）+ 管理面板 | ≈ +18 KB |
| T05 | 三个 AI 场景 UI + AI 服务设置面板 | ≈ +17.8 KB |
| 合计 | | **545 → 598.0 KB** |

### 为什么 T05 比 ARCH 估的 2 KB 贵了 9 倍

ARCH §1.7 给「D14/D15/D17 场景 UI」的预算是 2.0 KB，依据是「面板只是把预览和清单拼起来」。
实际落地的三块开销是估算时没算到的：

1. **`prompts.ts`（3.7 KB）与 `SuggestionList`（1.8 KB）在 T01–T04 阶段是被 tree-shake 掉的** ——
   没有任何代码引用它们。T05 一接线，这 5.5 KB 才真正进产物。
2. **三场景共用的主干本身就是一件产品**：预览 → 流式（含停止）→ 窄校验 → 建议逐条确认 →
   撤销，加上「未配置置灰 / 失败内联人话 / 只发勾选字段」这些不可省的诚实约束，
   主干 + 解析层实测 6.3 KB（`AiScenarioPanel` 3.5 + `scenarios` 2.8）。
3. **AI 服务设置面板 4.2 KB**：三个输入 + 两个预设 + 三句必须说清楚的风险提示。
   它的中文文案占了过半 —— 而这个产品的「可信度」正是由这些文案承载的。

### 定稿与代价（诚实记账）

- **实测落点 598.0 KB**，红线定 **WARN 585 / FAIL 600**，余量只剩 **1.9 KB**。
- 600 是「不再抬到 600」这张支票的**边界线**，本版把它用满了。因此写死一条约束：
  **v0.8.1 的第一件事是体积优化**（看板窗口化 + 文案复用 + 场景面板合并），
  把落点压回 ≤585 KB；不达成就**不排任何新功能**、v1.0 不启动。
- 做过的收紧：三处场景说明文案压缩（约 −0.4 KB）、三个场景包装组件合并为一个通用面板
  （−1.9 KB）、测试改为按 DB 造数而非 props 注入（0 KB，但更贴近真实用法）。
- 明确不做：不砍 D15 或 D17（都是 P0）；不砍设置页的风险说明（可信度由它承载）；
  不砍字段默认不勾的基线（那是 D13 的全部意义）。

## 7. AGENTS 边界（AI 与插件的权限边界）

这一版第一次让「外部智能」进入这个产品，所以边界要写在文档里，而不只是写在代码注释里：

| 主体 | 可以 | 不可以 |
| --- | --- | --- |
| 内置 AI 场景（D14/D15/D17） | 读**用户勾选**的字段；产出 `AISuggestion` | 直接写 `applications` / `questions` / `notes`（必须经用户确认 + `acceptSuggestions`）；读未勾选的库内字段 |
| D17 | 写 `staging.parsed`（缓冲表） | 碰 `applications`；发送原文之外的任何内容 |
| 插件 | 经宿主 RPC 申请：读投递（已授权时）/ 提交建议 / 用自己的存储 / 请求 AI（过 D13） | 自己 `fetch`（CSP 拦截）；跨 pluginId 读写；绕过预览；写核心表 |
| 任何自动化 | — | 自动合并、自动修复、自动改用户数据（PRD §7 明确不做） |
| 网络 | 只有 `app/src/ai/gateway.ts` 一处 `fetch`，且只在用户确认发送后 | 打开页面时任何请求；上报；检查更新；远程字体/图标 |

`check-no-network` 11 条规则照扫，`no-network-allowlist` 保持为空；
gateway.ts 的 `fetch` 是**结构性单点放行**（只豁免这一条规则，另有专项审计）。

## 8. 性能基准（`npm run bench`，headless Edge + file:// + localStorage）

500 条档位（验收 15 要求：今日待办 < 60 ms、看板 < 120 ms）：

| 指标 | 50 | 200 | **500** | 1000 |
| --- | --- | --- | --- | --- |
| 首屏 FCP (ms) | 108 | 84 | **80** | 100 |
| 列表排序一次 (ms) | 20.4 | 10.9 | **11.3** | 17.1 |
| 今日待办切换 (ms) | 32.1 | 33.5 | **30.7** ✓ | 27.9 |
| 看板切换 (ms) | 78.2 | 81.2 | **147** ✗ | 259.9 |
| 渲染行数（窗口化后） | 50 | 15 | **15** | 15 |
| 堆内存 (MB) | 10 | 10 | **10** | 10 |

- 今日待办 30.7 ms ✓ 达标。
- 看板 147 ms 超出 120 ms 线 27 ms：口径是「点『看板』→ 两次 rAF（含布局与绘制）500 张卡片」。
  这是**无虚拟化的绘制成本**，不是派生计算（派生索引 `buildNoteIndex` 已按一次扫描做）。
  达标需要给看板列做窗口化，属于 v0.8.1 的体积/性能任务（会与本次 8.5 KB 超线一起处理）。

## 10. 已知限制

- `Question.category` 没有被 AI 写入：D14 的产出带了类别，但新建题的写入路径目前只处理
  `text` / `myAnswer` 两个字段（写类别需要给 `suggestions.writeTarget` 扩一条分支）。
  题目会以「未分类」落地，你可以在编辑器里补一次。
- 看板 500 条绘制 147 ms（见 §8，v0.8.1 做窗口化）。
- 体积 598.0 KB，红线 600 只剩 1.9 KB 余量（见 §6）。
- 模型名不预填：预设只填地址，模型名需要你自己确认（每台机器装的模型不一样）。
