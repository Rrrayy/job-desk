# v0.4.1 · 把「出事的时候」也做完

> 发布日期：2026-10-21 ｜ 上一个版本：[v0.4.0](RELEASE-NOTES-v0.4.0.md) ｜ 完整变更：[CHANGELOG.md](../CHANGELOG.md)

**一句话**：这一版不给你新功能，只保证三件事 —— **崩了不白屏、删错能撤回、版本不再各说各话**。

## 🧯 崩溃兜底：白屏 → 三个出口

之前如果某个视图渲染抛异常，React 会卸载整棵树：用户看到纯白页面，数据还在 localStorage 里，
却没有任何办法拿出来。

现在会进入「你的数据还在」兜底页：

| 出口 | 作用 |
| :--- | :--- |
| 重新加载 | 大多数情况下刷新就好 |
| **下载原始数据** | 直接下载 localStorage 原文（标准 JSON，修好后可导入） |
| 复制错误信息 | 连版本号、UA、堆栈一起复制，方便反馈 |

兜底页**不写任何 key、不自动修复数据** —— 崩在渲染层时，任何「顺手清一下」都可能把仅存的一份数据覆盖掉。

## ↩️ 撤销 10 步 + 重做

- `⌘Z` / `Ctrl+Z`：连续撤销，最多 **10 步**（每步都是字段级快照，不是整库回滚）
- `⇧⌘Z` / `Ctrl+Y`：重做
- **删除投递现在可撤销**：面试、时间线、面经绑定会一起放回；
  面经如果已经被你改绑到别的投递，撤销不会把它抢回来

同步合并仍可撤销，但不可重做（当时的合并计划已经消费掉），会明确告诉你原因。

## ⚠️ 重复投递提醒

同一个「公司 + 岗位」再记一次时，会先提示已有记录：

> ⚠ 已经记过同一家同一个岗位：**已投递** · 投递于 2026-10-12。确实是又一次投递，就再点一次保存。

只做精确匹配（忽略空白与大小写），**不做模糊匹配** —— 「前端开发」和「前端开发工程师」是两道投递，
误报比漏报更烦人。第二次点击「仍然保存」就会正常写入，不拦真实需求。

## 🏷️ 版本号终于只有一个来源

审计时发现三处各说各话：

| 位置 | 之前 | 现在 |
| :--- | :--- | :--- |
| 设置页「关于」 | 写死 `v0.2` | 构建期注入 `v0.4.1` |
| `extension/manifest.json` | `0.2.0`（落后两个版本） | 与主应用同版本，打包时强制对齐 |
| Release 产物 | `manifest.json` 日期写死 `2026-10-20` | 每次发版显式指定 |

CI 新增第 7 关 `check:versions`：主应用、扩展、产物三处版本不一致，直接红。

## 💾 备份提醒与空间清理

- 设置页显示**上次备份：N 天前**；超过 7 天或从未导出时标红提示（只提示，不弹窗挡路）
- 显示迁移回滚点占用，可一键清理；**只删 `preMigrate.*`，绝不动 `failedAt.*`**
  —— 后者是读不出来的坏数据的唯一副本
