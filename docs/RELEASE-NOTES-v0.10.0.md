# v0.10.0 · 模型层全面升级

> 发布日期：2026-11-09 ｜ 数据格式：`schemaVersion 5`（**未变**）｜ 可回滚到 v0.9.2

## 为什么做这一版

v0.9.2 的 AI 有一个尴尬的分裂：**接入层很扎实**（唯一 fetch 出口、双超时、SSE、只发勾选字段），
但**分析层很薄** —— 八个场景的提示词都不超过 10 行，没有正例反例，解析失败就放弃；
而「竞争力分析」这个最需要 AI 的功能，实际上只发出去一份 JD。

也就是说：管道修得很好，但管子里流的东西不够。这一版补的是后者。

一句话目标：**让每一份 AI 结论都能追到原文，让每一次失败都能自己救回来，让每一分 token 都看得见。**

## 三个最值得说的改动

### 1. D20「竞争力分析」终于知道你是谁

之前它只发 JD、公司、岗位、状态。模型拿着一份岗位描述，被要求分析「候选人的竞争力」——
它唯一能做的就是顺着 JD 夸一遍岗位要求，`evidenceFromResume` 要么空着，要么编。

现在出境字段多了 `selectedModules`（默认不勾，有勾选框），面板可以选 1–3 个简历模块；
prompt 里写死了硬约束：**没给简历就全部 not_found，并在 summary 里说明「未提供简历」**。
宁可给一份「材料不足」的报告，也不给一个 82 分。

### 2. 提示词从「要求」变成「要求 + 正例 + 反例」

每个场景都补了正例与反例，反例写的就是模型最常见的三种坏法：JSON 前后加「好的」、
用 ` ```json ` 包裹、把不存在的经历编进去。

prompt 体积从 3 KB 涨到 9 KB —— 这是这一版最值的一笔开销。省 prompt 等于省产品上限。

### 3. 解析失败不再是死路

解析器说不合格时，会把**模型上次的原始输出**放回对话，追加一句「只谈格式」的修复指令，
temperature 0 再要一次。保留原对话是关键：去掉 system，模型就不知道「约定格式」是什么，
只会把它当新任务重新发挥。

修复请求自己失败时，返回原文的错误 —— 不让用户面对「修复也失败了」这种二级错误。

## 升级与回滚

- **升级**：替换 `index.html` 即可。新增字段（`temperature` / `topP` / `maxTokens` /
  `jsonMode` / `timeoutSec` / `lastCheck` / 日志的 `tokens` 与 `durationMs`）全部可选，
  老数据读出来就是「没配这些参数」，行为与 v0.9.2 一致。
- **回滚**：直接换回 v0.9.2 的 `index.html`。`schemaVersion` 没动，v0.9.2 不会因为
  多出来的字段而拒绝读取（`normalizeAiSettings` 白名单会丢弃未知键）。

## 已知边界（有意为之）

- **不给简历诊断分块**：切块会把「整体对照」降级成「片段比较」，明知有害所以只给面经拆题用。
- **不做启动探测**：测试连接只在点击时发生，`ready` 仍只看地址与模型名是否为空。
- **D17 / d19-jd 不猜字段**：证据对不上时只摘证据、不动内容 —— 写错数据比少一条建议严重。
- **`aria-live` 无自动化断言**：属性存在性测试容易变成「测字符串」，这条靠人工审阅，不假装有测试。
