## 这一版在解决什么

v0.2 已经能记投递、能看板拖拽、能从平台文本同步状态。但用一段时间后暴露出三个真问题，
它们是这一版的全部动机 —— 不是「加了几个字段」，而是**三处会让人误判的地方**。

### 1. 「截止」之前根本不存在

v0.2 只有「沉默」：对方不理我多久了。但求职里还有另一件事：**外部世界给我设的期限**。
「周三 18:00 前确认笔试」「Offer 三天内回复」—— 这类事和「HR 已读不回」是**两条正交的轴**，
之前一条都没有。

v0.3 加了应用级 `deadlineAt`，三级紧急度（已过期 / 今天截止 / 3 天内），
投递截止和 Offer 回复截止共用一条轴 —— 一天只有 24 小时，不该因为截止的种类不同就提醒三遍。

`deadlineAt` 是**三态**的，这是本版最容易写错、也最值得说清的设计：

| 值 | 含义 |
| --- | --- |
| `undefined` | 继承上层默认（当前没有 Season 实体，等价于「未设置」） |
| `null` | **用户显式关闭**这个提醒 |
| 具体日期 | 覆盖 |

为什么非要分 `undefined` 和 `null`：导入历史备份时，缺失字段如果被读成 `null`，
就等于「用户主动关掉了提醒」，这家公司从此再也不会提醒截止 —— 而用户从没做过这个决定。
校验器里专门写了 `asTriStateDate()` 守这条线，`null` 和 `undefined` 必须分开走。

### 2. 最贵的沉默，恰好不报警

v0.2 的沉默监控只覆盖 `applied` / `chatting` / `interviewing` 三个阶段。
**`offer` 阶段不在里面** —— 而「Offer 发了一周没回音」是整个流程里最贵的那次沉默，
它意味着你可能同时丢了保底和冲刺。

v0.3 把 `offer` 纳入沉默计算，阈值走独立的 `offerSilenceDays`（默认 7 天，第 4 天提醒），
并且**不乘渠道系数**：内推 ×3 会把 7 天变成 21 天，等于永不提醒。

### 3. 今日视图件数一多，就等于没有今日视图

12 件待办和 0 件待办，对用户是同一种效果：不看了。

v0.3 加了**每日行动预算**（默认 5 件）：默认只显示最靠前的 5 件，其余折叠成
「还有 N 件，展开看」。排序即优先级 ——

1. **红**：截止已过 / 今天截止、沉默超过阈值
2. **蓝**：今天有面试、面试该记结果了
3. **黄**：即将截止、该催了、想投太久没动

还有一个刻意的限制：**截止项不能一键划掉**，只能打开详情。
截止是外部事实，不是「我做完了」—— 让它能被一次点击消掉，就等于允许自己骗自己。

## 新增的两个开关

**「暂时别催」** —— 详情抽屉里可以静音 3 天 / 7 天，到期自动恢复。
静音落在第 N 天的 23:59:59，不是 `now + 72 小时`：用户说的是「这三天别烦我」。

**关键边界：静音压得住软提醒，压不住硬截止。**
算法推断的「该催了」可以静音；外部世界给我的「明天 18:00 截止」不能静音。
截止项在静音判断**之前**就算完并保留 —— 这条写进了执行顺序，也写进了单元测试。

## 给别的软件看的导出

只有 JSON 能导入回来，但数据不该被锁在这个工具里。

- **投递表 CSV**（15 列）：Excel 双击直接打开，不乱码（UTF-8 BOM）。
  以 `=` `+` `-` `@` 开头的单元格会前置单引号防公式注入，但纯数字不误伤 ——
  薪资写成 `-200` 是很正常的事，不该被当成攻击。
- **面试日历 ICS**：可导入系统日历 / Google Calendar。
  按 RFC 5545 折行（每行 ≤75 **字节**，中文一个字 3 字节，按字符切会切出半个字符）；
  `UID` 稳定，重复导入不会造重复日程；已取消的面试导 `CANCELLED`。

## 升级

**直接替换 HTML 文件即可。** 数据在浏览器 `localStorage` 里，不动它就不会丢。

- `schemaVersion` 仍是 2，**没有不可逆迁移**。
- 只新增了 `Application.deadlineAt` / `mutedUntil` 和 `AppSettings` 的三个阈值，
  都是带默认值的可选字段。
- 老备份导入照旧：缺字段补默认值，不拦、不警告、**不覆盖你改过的阈值**。
- 从 v0.1 的数据库升级也仍然走同一条 `migrateV1ToV2` 路径。

第一次打开建议先去**设置 → 数据 → 导出 JSON** 存一份。不是因为这个版本危险，
而是因为「没有回收站」这个限制从 v0.1 起就没变过。

## 已知限制（不藏）

- **撤销只有一层**：`⌘Z` 退一步，连按不会继续往前退（v0.4 换 10 层栈）。
- **截止只有应用级**：还没有「整个招聘季的截止」，每条要单独填（v0.4 补 Season）。
- **没有回收站**：删投递是即时的，有二次确认但删了就没了。
- **同步是文本解析，不是接口**：平台改版会让解析失效。失效时说「没解析出来」，不会静默丢数据。
- **BOSS / 实习僧 / 牛客的选择器未在真实登录页验证**：fixture 是构造的。
  扩展给你的是「页面文本 → 记录」，解析错了会进「待归类」，不会直接写库 —— 但准确率需要真机校准。
- **移动端只是能用**：窄屏做了适配，拖拽和快捷键是桌面优先。
- **秋招量级只做了算法级优化，没有实测**：150+ 投递的端到端耗时尚无基准。

## 下一版（v0.4）

主线是**数据模型重构**，不做新功能堆叠：

- 招聘季（Season）+ 双层截止：赛季级截止 + 公司级覆写，`effectiveDeadlineOf()` 唯一入口
- `stage(7) × outcome(5)` 双轴取代单一 status（`scheduled` 改派生，`offer` 升实体）
- 轮次语义化：一面 / 二面 / 交叉面 / HR 面各自建模
- 撤销栈：单槽 → 10 层 LIFO
- `staging` 超 200 条时先告知再丢

完整评审与验收标准见 [`docs/ROADMAP.md`](ROADMAP.md)。
