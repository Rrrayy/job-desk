# v1.0.0 · 投递之后

> 发布日期：2026-11-10 ｜ 数据格式：`schemaVersion 6`（**空迁移**）｜ 可回滚到 v0.10.0

## 为什么是 1.0.0

CHANGELOG 顶部有一段旧话，解释 v0.2 为什么把 `1.0.0` 退回成 `0.2.0`：
「没有测试、没有 CI、没有数据迁移、没有适配器协议、没有一行文档 —— 一个会被真实数据长期持有的工具，
`1.0.0` 应当意味着格式稳定、升级可回滚、有回归测试」。

那五件事现在都在了：91 个测试文件 / 1473 条断言、六道关卡、
v1→v6 六次迁移每一次都能回滚、适配器协议有 `docs/adapters/`、文档与本机数据同源。
所以这一次的 `1.0.0` 不是自我感觉良好，是把当初写下的三个条件逐条对上了。

## 一句话目标

**投递之前的账，v0.1 就算得清；投递之后的账，这一版才第一次算清。**

拿到 Offer 之后要权衡什么、这家公司到底什么样、聊完一句「下周三二面」怎么三秒钟记下来、
七家静了半个月该先催谁 —— 这四件事以前全靠脑子，现在各有一个模块。

## 四个模块

### 一 · Offer 决策台

九个字段（月薪 / 薪数（含年终）/ 日薪 / 签字费 / 通勤 / 职级 / 股权原文 / 截止日 / 备注），
四维自评（薪资 / 成长 / 城市 / WLB），权重可调、恒定合计 100，最多八个并排比。

三个刻意的「不」：

- **缺的维度不按 0 分算**，只在已评维度上归一，并在分数旁标「按 2/4 维归一」
  —— 归一不说明，分数就是骗人的；
- **权重不是「这一次比较的参数」**，改完一直生效，因为它是你的判断标准；
- 免责句只有一个落点：「分数帮你排清偏好，不替你做决定」。

决策会留档（选谁 + 理由标签 + 一段话 + 放弃了哪几个），改选要再点一次才覆盖。导出的 Markdown
最后一行永远是那句免责声明。记录里指的投递**被删了也不拦**（显示「（投递已删除）」）——
否则「删一家 → 导出 → 导入」会让整库导入失败。

### 二 · 公司档案

详情抽屉里的公司名变成可点。档案按「概览 → 小计 → 投递 → 面试 → 这家的面经 → 时间轴」排，
空字段不产生行（不写「规模：—」这种占位）。

「员工口碑」新开一个字段，不和「面试体感」合并 —— 合并的结果是用户永远只填一种，
而这两件事一个是别人说的、一个是你亲身遇到的。

「去题库复习这批题」会带着这家公司的名字跳过去，筛出来的题数与档案里的题数必须是同一个 N。

### 三 · 一句话快记

「明天下午 3 点字节二面」→ 本地词表解析 → 确认条 → 点保存才写库。**零网络请求**。

这个模块的全部价值观是**猜不准就问**：

- 公司三态都摆出来：唯一就填好；两家可能就要求点一下；一家都不像就给「新建公司『X』」；
- 这家公司有两条以上投递时，岗位一律留空；
- 时间只有日期（「明天」）或只有时刻（「3 点」）就不建面试 —— 建了也是错的日历；
- **面试形式解析不出就留空并要求手选**，绝不默认「视频」；
- 状态建议默认不勾：一句话不该把整条管线改掉。

没听懂就老实说没听懂，原文一个字不动，给一个「改用手动记录」把这句话交回表单。
停手 400 ms 才解析 —— 逐字解析会让确认条在打字过程中反复变身，用户看不清也没法点。

撤销粒度是「一次写库一个点」，所以 toast 说的是「已记录 N 项，**可逐步撤销**」。
记「面试 + 状态变更」要按两次 ⌘Z，这是为了不新开第二条写库路径付出的代价。

### 四 · 沉默待办

列表页多一个页签：红「已沉默」/ 黄「该跟进」两组，红组里 15 天处一条分割线。

- 分组**只看沉默等级**，不按天数硬切 —— 内推阈值是 ×3，所以「内推 10 天」是黄不是红；
- 分割线不是子组 —— 只有一套计数口径，用户才对得上账；
- 静音的条目**仍留在原组**（灰显 + ⌛），勾「隐藏」才藏起来：否则「7 条」这个数字会随静音状态变化；
- **批量催问是两步的**：生成话术 ≠ 发了消息，只有勾了「已发出」的才写记录
  —— 一步到位会把没发的记录全刷成绿色，那是在骗自己；
- **批量放弃一次 ⌘Z 整批回滚**（一个撤销点，不是 N 个）；
- 静音到 3 天 / 下周 / 指定日期，统一到当日 23:59:59（「静音 3 天」= 这三天别再提它）。

## 数据格式

`schemaVersion` 5 → 6，`formatVersion` 4 → 5。

**5 → 6 是一次空迁移**：只改版本号 + 记一条 `lastMigration`，不补字段、不造默认值。
所以：

- 迁移后的库与迁移前**逐字段 deep-equal**（除了那两行）；
- 迁移**幂等**（再跑一次引用都相等）；
- `settings.offerWeights` 迁移后仍是 `undefined` —— 缺省值只活在代码里，
  迁移替你写权重等于替你决定价值观；
- v0.10.0 读这份库时会忽略多出来的可选字段，回滚是干净的。

## 已知边界（如实标注）

- 快记是**词典 + 规则**，不是模型。它认识「明天下午 3 点」「下周三」「二面」「视频」，不认识
  「国庆后那周」这种说法 —— 认不出就问，不猜。
- 「薪数（含年终）」是一个数，年终奖不单独记：拆成两个字段会让「14 薪」到底怎么算变成一道多选题。
- 批量放弃的撤销回滚的是字段级差异（状态 / 两个时间戳 / 挂的轮次 / 那条自动记录），
  不是整库快照 —— 撤销一次批量放弃不会把「刚记的一场面试」一起退回去。
- 对比表一屏最多 8 个 Offer。再多就该先筛掉几个，而不是挤成一条线。
- 撤销**不还原** `updatedAt` 与 `userEditedAt.status`：撤销本身也是一次写，`updatedAt` 刷新是合理的；
  副作用是同步引擎仍会把这行当成「用户手动改过」——这是 v1.0.0 之前就有的行为，本版未改。
- 快记一次写库 = 一个撤销点：记「面试 + 状态变更」要按两次 ⌘Z，toast 会如实写明「已记录 N 项」。
