主题：**把手里的数据交给一个文件**。数据模型升到 v3，工作台可以绑定你自己选的文件自动写盘，备份可以加密，导入不再需要手抄表头。

---

### 新增 · 文件联动（D8）

「数据只在浏览器里，换台机器就没了」是这个产品一直存在的缺口。导出 JSON 只解决了一半 —— 用户还得记得导。

现在可以在设置里把工作台绑到一个 `data.json` 上，之后每次改动自动写进去。这件事听起来只是省一次下载，实际要处理六层失败，每一层都对应一种「用户以为保存了，其实没有」：

| 层 | 做什么 | 不做会发生什么 |
| :--- | :--- | :--- |
| 写入队列 | 同一时刻只跑一个写事务，期间的新请求只留最后一版 | 连续改十次并发写同一个文件 → 文件被写坏 |
| write-ahead 缓冲 | 写之前先落一条记录（内容摘要 + 待写文本） | 写到一半关掉浏览器 → 这次编辑凭空消失 |
| 冲突检测 | 写前重读文件算 SHA-256，与「上次我们写完后的摘要」比对 | 用户在别处改过文件 → 被静默覆盖 |
| 原子提交 | `close()` 才算提交；旧文件更长时补 `truncate` | 尾巴残留 → 文件变成一段坏 JSON |
| 句柄身份 | 只认 `isSameEntry`，不认文件名 | 两个同名文件 → 把 A 的内容写进 B |
| 权限重请求 | 每次加载重新请求，且必须在点击里 | 启动时自动请求 → 被浏览器直接拒，功能像坏了 |

冲突的处理方式是**不覆盖**：另存 `data.conflict-YYYYMMDD-HHMMSS.json`（里面是外部版本 + 检测时刻 + 我们的基准），主文件一个字不动。如果连冲突副本都写不出来（句柄拿不到所在目录），引擎放弃本次写入并如实报告 —— 宁可这次没保存，也不静默覆盖。

权限被收回时进入**只读锁定**，永远给三个出口：下载原始文件 / 重试 / 另存为新文件。原始数据绝不自动修改或删除。

> **能力不够就说实话**：Safari / Firefox / 移动端没有 File System Access，面板上直接显示「不支持」并说明降级为手动导入导出；`http://` 打开时显示「需要 https」。不做一个点了没反应的按钮。

### 新增 · 数据模型 v3（D9）

`schemaVersion` 2 → 3，`formatVersion` 1 → 2。

- `events`（日程）additive 扩展三个可选字段：`applicationId` / `color` / `notes`。**不凭空填值** —— 老数据读进来是什么样，写回去还是什么样
- `AppSettings` 新增 `backupReminderDays`（0 / 3 / 7 / 14，非法值回落 7）、`fileLink`、`encryption`
- 迁移链 `v1 → v2 → v3` 级联、幂等、迁移前写回滚点、失败不动原数据。启动迁移与导入备份**走同一份实现**（`migrateV2ToV3`），避免两条路径以后走岔
- **v0.5 导出的 JSON 能被 v0.6 直接导入**，这一条写进了测试

### 新增 · 可选加密（D10）

AES-256-GCM + PBKDF2-SHA256 60 万轮。默认关闭，需要在设置里主动开启并设口令。

- 每次加密新生成 12 字节 IV 与 16 字节 salt，绝不复用（GCM 下 IV 复用等于整段作废）
- `extractable: false`，密钥不能被脚本导出
- 信封是**纯 JSON**：没有口令也能判断「这是一份加密备份」，用文本编辑器打开看到的是说明而不是乱码
- GCM 认证失败直接报错，绝不返回半截明文；`iterations < 10 万` 的信封直接拒绝解密
- 关闭加密**也要口令**：已经写出去的文件是加密的，不确认能读出来就关，等于下次把加密文件覆盖成明文
- 加密开着但本次会话没有口令时，**拒绝导出**并提示去设置输口令 —— 不静默降级成明文

> **诚实声明（设置页原样展示）**：前端加密不能抵御 XSS 或恶意浏览器扩展对运行时内存的攻击。它的作用是：当备份文件落到网盘、U 盘或别人的电脑上时，没有口令就读不出内容。口令不会被保存在任何地方，忘记口令后这份备份无法恢复。

### 新增 · 导入字段自动映射（P1）

- **CSV 导入**：手写 CSV 解析（引号包裹、引号内逗号与换行、`""` 转义、CRLF、BOM），表头按别名表映射到字段，最多识别 13 个字段
- **认不出的列必须列出来**：预览里用灰色的 chip 显示「列 → 忽略」，鼠标悬停给原因。消失等于悄悄丢弃
- **先预览再落库**：列映射、前 8 行、逐行问题（日期认不出 / 状态认不出 / 缺公司名）三块都给，确认后才合并
- 没有表头的文件按「第 1 列公司、第 2 列岗位」推断，并在预览第一行明确说这是推断
- 去重键与 JSON 导入**完全一致**（公司名归一 + 岗位 + 投递日），不会出现「JSON 导入去重、CSV 导入重复」两套语义
- 备注列的落点是 `memo` 时间线而不是投递字段（`Application` 上没有 notes），内容里标来源

### 新增 · 备份提醒可配置（P1）

设置 → 关于里可选「不提醒 / 3 天 / 7 天 / 14 天」。开启文件联动后，文案降级为「建议定期导出快照」——因为自动写盘不等于备份，换浏览器照样丢。

## 为什么体积是 531 KB

这一版从 480 KB 涨到 531 KB，越过了原来的 490 KB 警戒线。在动阈值之前先做了构成测量：

| 项 | 压缩后 | 说明 |
| :--- | ---: | :--- |
| React 18 + react-dom（生产版） | 142 KB | 硬地板，砍不掉 |
| 本轮新增 6 个模块 | 28 KB | crypto 5.6 / csvImport 6.9 / link-engine 10.3 / handle 1.5 / pending 1.4 / hash 2.3 |
| 新增 2 个面板 | 13 KB | 文件联动面板 + CSV 预览对话框 |
| 其余 | — | `App.tsx` 接线、设置页、迁移、样式 |

新增的 UI 不是虚胖：产物里 1307 处 `className`、1467 处 `children`、约 15 K 汉字的产品文案，其中很大一部分正是「把风险说清楚」的那部分 —— 只读三出口、冲突解释、加密诚实声明。删它们省下来的 KB 比失去的可信度贵。

也试过别的路：terser 级别 mangling 能再省 40–50 KB，但要引入 `terser` 依赖，与「构建链不加依赖」的承诺冲突；CSS 变量名压缩约 4 KB，收益与改动风险不成比例；ES module 分包会让 `file://` 双击失效，直接违反产品立身之本。

所以这一版的选择是：**承认体积上了一个台阶，同时只把 FAIL 从 540 抬到 560**（现有 +29 KB 余量，约等于「再做一个中等功能就要先优化」）。不一次抬到 600 —— 那正是 v0.3 批评过的「空白支票」。gzip 后实际 159 KB，`file://` 打开是本地读盘，不受网络影响。

下一版起默认不再动 FAIL，红线回到「每版只随基线浮动」的节奏。
