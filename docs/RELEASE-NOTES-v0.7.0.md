# v0.7.0 · JD 链接延伸 + BOSS 卡片解析

主题：**链接存进来，就该能用**。

## 修复：BOSS 求职记录卡片解析失败（真机报告）

用户 2026-10-21 从 BOSS App 复制单张求职卡片（Agent 研发实习生 / 杭州芯流微澜智能科技），
整条落进「待归类」：招聘者姓名「杨琪 招聘者」被当成公司名，岗位行与公司行各自报
「这一行没有公司名」。

根因：这是**卡片形态**——各视觉行之间是空行，与已校准的求职记录列表页不同，
复制出来后被空行分块切成三块，每块独立解析全错。卡片形态的特征（卡片头「X 招聘者」、
方括号地点、「公司名 行业 0-20人」无融资阶段）此前一个都没处理。

修法（全部在 BOSS 适配器内部，共享引擎不加平台 if）：
- 卡片形态判定 + 预处理：丢卡片头、拆方括号城市、剥「行业+规模」与学历标签，
  一张卡恰好一个块 → 恰好一条记录；
- 顺带修掉一个潜伏缺陷：城市行「杭州-萧山区·宁围」里的连字符在公司名字符集里，
  会被当成公司名——现在纯城市形态不参与公司名候选，
  以城市词开头的真公司名（杭州芯流微澜智能科技）靠公司名收尾词放行，不误杀。

## 新增：JD 链接延伸

`jdUrl` 此前只是一个字符串：存得进去，拿不出来——点开要回平台重登，职位下架就归零。
本版把链接变成能用的东西，全部零网络（跳转是浏览器行为，应用不发任何请求）：

| 能力 | 说明 |
| --- | --- |
| 一键打开 / 复制 | 详情抽屉 JD 区块；非 http/https 不渲染跳转（URL 来自导入，是不可信输入） |
| 快捷键 J | 抽屉打开时按 J 直接打开 JD；输入框聚焦不触发；已标记失效则不动 |
| 标记失效 | `jdLinkDeadAt`，可恢复 ≠ 删除；职位下架时不用反复点开碰壁 |
| 粘贴 JD 正文解析 | 复用详情页解析器 + 新增章节抽取（职责/要求/加分项/安排，只认显式标题行） |
| 原文留档 | `jdText`（≤20,000 字符，超出拒绝保存不静默截断）+ `jdCapturedAt` |

### 解析结果为什么默认不写入

解析是「我想看看这里面有什么」，不是「我要存」。待确认区六项识别状态永远全显示
（识别 / 未识别 + 原因），逐字段勾选「采用」才落库；已有值时明示「当前 X → 解析 Y」。
公司名只展示不建议写入——公司名挂在公司上，改名影响全部关联投递。
JD 原文不碰时间线与 `lastActivityAt`：贴 JD 不等于有进展，沉默标红不能被它消掉。
