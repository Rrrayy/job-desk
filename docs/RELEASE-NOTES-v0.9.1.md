# RELEASE NOTES v0.9.1「遗留问题清理版」

> 这一版**没有新功能**。它只做一件事：把 v0.9.0 里「说了要做 / 做了但没告诉用户 /
> 根本没做却写进了文档」的地方逐条兑现，并顺手把产物减了 8.6 KB。
>
> **数据格式零变化**：`schemaVersion` 仍为 5、`formatVersion` 仍为 4，
> 没有新增迁移步骤。老数据直接打开即可，回滚到 v0.9.0 也不会读不懂。

## 1. 体积：先还债，再花

| 项 | 实测 | 预算 |
| --- | --- | --- |
| 起点（v0.9.0 产物） | 719,686 B = **702.8 KB** | — |
| T1 类名 token 化 + 主版本提示 + 勘误 | 710,872 B（**−8.61 KB**） | −9.2 |
| T2 旧数据归类 + 改绑撤销点 | 717,201 B（+6.18 KB） | +3.5 |
| T3 回收站分区 + 报告历史 + 配额告知 | 723,004 B（+5.72 KB） | +6.0 |
| T4 看板窗口 + 简历到期告知 + 启动告知 | 724,630 B（+1.59 KB） | +3.5 |
| T5 打印 hint 层 + 发布脚本 + 文档 | 725,474 B（+0.82 KB） | +0.5 |
| **落点** | **725,474 B = 708.5 KB（累计 +5.65 KB）** | — |

**类名 token 化**（−9.58 KB 是 T1 单项贡献）做的是这件事：产物里 1,700+ 处 `className`
字面量中，100 个高频长串（`btn btn--small` × 76、`field__label` × 75 …）占了接近六成出现次数，
把它们收进一张运行时映射表 `CLS`，源码写 `CLS.a`，**运行时求值出的仍是原串**。

为什么选「运行时映射」而不是「构建期改名」：DOM 输出逐字节不变，所以
105 处测试类名断言、61 处 CDP 选择器、DevTools 里看到的东西全部不受影响。
这一点有三重证明：既有测试全绿、`SendPreviewDialog` 的整树 `outerHTML` 快照不变、
以及 `node scripts/tokenize-classes.mjs --audit <token 化之前的 ref>` 把 960 处替换
**逐字节逆变换**回原文件后与 git 历史完全相同。

**这一版越过 v0.9.0 的 WARN（705 KB）3.5 KB、离 FAIL（730 KB）还有 21.5 KB**，
阈值由主理人按实测数裁决调整，本版不改 FAIL。
写在这里是因为——涨红线不是技术决策，是产品决策，必须留痕。

## 2. 让「静默」变成「说出来」

v0.9.0 里有一批**代码替用户做了决定却不说**的地方，本版逐个补齐（铁律 6：不许静默）。

1. **主版本指针变了会说**（T1-b）。设主版本 / 删版本 / 永久删版本 / 永久删简历，四条路径
   都会改写 `settings.defaultResumeVersionId`，而它决定「新建投递默认绑哪一版」。
   v0.9.0 里四条路径全静默 —— 用户毫不知情，下一次新建投递就绑到了另一份（或没有）版本上。
   现在统一出口给一句话：「主版本已从『前端-投递版』改为『前端-精修版』」。
2. **简历满 30 天被永久删除会告知**（T4）。`sweepTrash` 从 v0.9 起就算出了
   `removedResumes` / `removedVersions`，但**从来没送到界面上** —— 简历到期是真删，
   却是全静默的。现在启动时按优先级报：「回收站里有 1 份简历和 5 个版本已满 30 天，已自动永久删除」。
3. **简历即将到期会提醒**（T4）。此前只有投递侧提醒，简历侧没有。口径与投递一致（剩 ≤3 天）。
4. **报告被顶掉会说**（T3）。同一目标只留最近 3 份报告，v0.9.0 连点第四次诊断时，
   最早那份就悄无声息地没了。现在两处都说：
   - 发送**之前**（目标已有 3 份时）黄条写明「新生成的这份会让最早的一份（10/21 10:00）被顶掉」，
     并给「先删最早一份」的显式入口；
   - 生成之后若确实顶掉了，toast 补一句「最早那份已被顶掉」。
5. **全库报告配额满了会拦住并给出口**（T3）。到 200 份时不再「生成完再悄悄丢一份」，
   而是把「预览」置灰并说明「先在报告历史里删几份旧的」。

## 3. 补上的能力（都是 v0.9.0 文档里承诺过的）

### 3.1 旧数据逐条归类（T2）

v0.9.0 把早期投递（只有手写的 `resumeVersion` 文本、没有 `resumeVersionId`）统一归进
「未绑定（旧数据）」统计。本版给它们一个**逐条**归类入口：简历页顶部横幅 + 列表视图的
「未绑定」筛选里各一个入口，同一条只问一次。

- **零 schema 变化**：写的是既有的 `Application.resumeVersionId`（通过既有 `bindResumeVersion`），
  不新增字段、不新增迁移。
- **不做批量**：可以「跳过（暂不归类）」「不属于任何版本」，两者都是**零写入** ——
  用户没表态就不能替他表态。「另有 N 条写的是同一个文本」只是提示，点一次只处理当前一条。
- **不动沉默天数**（F9 红线）：归类只改绑定字段，不写 note、不动 `statusChangedAt` /
  `createdAt` / `lastActivityAt`。有值断言钉着：归类前后 `lastActivityAtOf` 必须**逐值相等**。
- **归类前先说明**：「简历列显示为『X』（原文本『Y』不再显示）。投递 / 沟通 / 面试记录都不动，
  沉默天数也不会被重置。」

### 3.2 改绑可以撤销（T2）

v0.9.0 的发布说明把「改绑留痕」当卖点写了，但 `UndoEntry` 里根本没有改绑分支 ——
用户按 ⌘Z 撤不回来。本版补上，且**撤销粒度只回退一条投递的四个绑定字段**
（`resumeVersionId` / `resumeVersion` / `resumeBindLog` / `updatedAt`），不复制整条投递：
撤销一次绑定不该把「绑定之后用户又改的状态」一起退回去。

### 3.3 回收站里能找回简历（T3）

删除的简历此前**没有任何恢复入口**，只能等 30 天被永久删除。现在设置 → 回收站里多了
「简历（N 份）」子区：显示剩余天数（≤3 天转为到期告警色）、`含 M 个已删版本`、
「恢复」「再留 7 天」「永久删除（两步确认）」。

合并进设置而不单开页面，是因为「删了的东西在哪找回来」是**一个**心智模型；
两个入口会让用户忘了还有第二个。版本树也不在这里展开 —— 恢复一份简历，它下面的版本一并回来。

### 3.4 报告历史（T3）

同一目标的诊断报告可以**切换**着看（`‹ 2/3 ›`），并可以删掉某一份（两步确认 + 明写不可撤销）。
只有 1 份时连表头都不渲染 —— 与 v0.9.0 的样子完全一致，历史只在真的有历史时才有意义。
报告是 AI 的可再生缓存，删除**不进撤销栈**（撤销只回退用户亲手写的资产）。

### 3.5 看板窗口化（T4）

一列超过 40 张卡时只渲染 40 张，底部给「还有 N 家 ▾」显式展开。
**列头计数永远是真实总数**（不是已渲染数）——「投递中 87」不会因为窗口变成 40。

为什么是窗口而不是虚拟滚动：看板每列是独立拖拽落点，虚拟滚动要把落点判定改成几何计算，
拖拽、键盘可达、`⋯` 菜单三套交互都要重写；而真实痛点只是「一列 200 张时首屏慢」，
不是「内容无限长」。`npm run bench` 现在会打印实测渲染卡片数，并在任何一组数据超过
「列数 × 40」时**退出码 1** —— 免得「看板快了」变成无法证伪的说法。

### 3.6 打印提示按浏览器分支（T5）

提示层多一句按浏览器变的话（Chrome / Edge、Firefox、Safari 各自菜单在哪、缩放怎么选）。
**只有这一行字按 UA 变，打印 CSS 仍然只有一套** —— 三家浏览器在 A4 / 14mm /
`break-inside` 上的行为一致，为它们各写一套版式等于以后每次调分页都要验三遍。
`check:print` 里有一条反面断言盯着「不许出现 `@-moz-document`」。
另补了 `orphans: 3 / widows: 3`：`break-inside: avoid` 在「块比一页还高」时**必须**断开，
此时这两个属性决定断在哪，否则会出现「上一页最后孤零零一行字」。

## 4. 新发现的已知问题

### 4.1 `.btn--ghost` 是死类名（8 处按钮受影响）

v0.9.1 的类名 token 化在 round-trip 审计时发现：源码里有 8 处按钮写着 `className="btn btn--ghost"`，
但 `styles.css` 里**只有** `.btn--danger-ghost`，没有 `.btn--ghost` 这条规则。
也就是说这些按钮当前的**视觉与裸 `.btn` 完全相同**（没有专属样式）。

- 位置：`App.tsx`、`FileUpload` 系列、`AiScenarioPanel`、`SendPreviewDialog`、
  `SuggestionList`、`PluginsPanel`、`CsvImportDialog`。
- 现状：功能完全正常，只是「幽灵按钮」这个视觉意图没有实现。
- **本版不补**：补 CSS 会改变用户已经看惯的界面，而本版是清理版不是视觉改版；
  升级后外观突变会让人误以为坏了。且 ghost 到底长什么样需要视觉决策。
- 处置：记为 **v0.9.2 处理**。审计白名单 `KNOWN_UNSTYLED_ATOMS` 只放行这一个类名，
  **新增的死类名（比如拼错的类名）仍会让 `npm run check:classes` 红**。

### 4.2 `App.tsx` 仍然缺测试

本轮把启动告知的四条分支抽成了纯函数 `src/lib/startup.ts`（8 条测试），
但 `App.tsx` 本体仍是 3,000+ 行、全仓没有任何测试 import 它。
这属于既有技术债，本版没有解决，只保证**不再往里堆不可测分支**。

### 4.3 设置抽屉只有「薄」挂载测试

`ResumeTrashSection` 自身有 8 条测试，但它此前是**直接渲染**的 —— 组件对了、
没挂进设置页，用户照样看不到，而测试全绿。本版补了 `SettingsDrawer.test.tsx`（2 条），
从父级往下渲染一次，断言 `.resume-trash__title` 真的出现了（并做了变异验证：
把 `<ResumeTrashSection />` 摘掉，测试立刻红）。

但**只到「薄」这一层**：`SettingsDrawer` 是 5 个子组件的聚合容器，
内部的交互（导入 / 导出 / 清空 / 插件 / AI / 文件联动）仍然没有测试。
这是本版剩下的最大一块测试债，记为 v0.9.2 候选。

### 4.4 `api.ts:179,180` 的两条 eslint warning（已知，未修）

```
179:30  warning  `import()` type annotations are forbidden  @typescript-eslint/consistent-type-imports
180:31  warning  `import()` type annotations are forbidden  @typescript-eslint/consistent-type-imports
```

`BulkAdoptInput` / `BulkAdoptResult` 用了内联 `import('../ai/experienceBulk').X` 写法。
这两条是 **warning 不是 error**（`npm run lint` 退出码 0，`verify` 全绿），
改成顶层 `import type` 即可消除；本版不动它们，是因为本轮所有改动都必须服务于
「体积 / 静默 / 文档」三条主线，纯风格清理会让 diff 混入无关噪音。
本版确认过 `ai/experienceBulk.ts` 并不反向 import `lib/api`，**不存在类型环**，
所以将来改起来是安全的。

## 6. 升级与回滚

- **升级**：直接用新的 `index.html` 打开即可。localStorage 键仍是 `jobdesk.v1`，
  `schemaVersion` 仍为 5，不触发任何迁移。
- **回滚**：v0.9.1 没有写入任何 v0.9.0 读不懂的字段，回滚同样零操作。
- **类名 token 化对用户完全不可见**：DOM 里的 class 与 v0.9.0 逐字节相同，
  你自己写的插件 / 油猴脚本 / CSS 覆盖都不受影响。
